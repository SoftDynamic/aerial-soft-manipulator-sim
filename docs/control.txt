Gate C2-C2: compatible tendon bending acceleration control
===========================================================

Status and validity envelope
----------------------------

This design is accepted only for the calibrated fixed-root, vertical,
no-contact StableSoft plant over the measured 0.002--0.010 N tendon range.
It must not be treated as a globally calibrated free-flight, contact, or
large-deformation model.

The existing four-channel TendonContractionAccelerationController, four-value
RPM action, ideal-tension writer, MJCF, manifest order, actuator gear, and
0.01 N actuator limit are unchanged.  C2-C2 adds a separate compatible
controller; it does not replace those APIs.

Coordinates and public command semantics
----------------------------------------

Tendon corner order is resolved from manifest names.  In canonical order

    s = [s_xp_yp, s_xp_yn, s_xn_yp, s_xn_yn]^T

positive s means tendon contraction.  Define

        [1  1  1  1]              [q_common]
    G = [1  1 -1 -1]       q = 1/4 G s = [q_x]
        [1 -1  1 -1]                     [q_y]
        [1 -1 -1  1]                     [q_twist_candidate]

and s = G^T q.  Thus the compatible bending expansion is

    s = G_b^T [q_x, q_y]^T,    G_b = G[1:3, :].

The public two-dimensional input (a_x, a_y) has units m/s^2 and means
(q_x_ddot, q_y_ddot), tendon-modal contraction acceleration.  It is not UAV
or tip Cartesian acceleration, curvature acceleration, or motor/spool
acceleration.  Positive q_x and q_y bend toward +X and +Y respectively.

A four-tendon acceleration may still enter the new controller for migration
or diagnostics, but it is first projected by

    P_b = 1/4 G_b^T G_b.

For example, [100, 0, 0, 0] um is incompatible: its compatible part is
[50, 0, 0, -50] um and its bending coordinate is [25, 25] um.  A public
shape request should normally use the two-dimensional bending entry.

Reference, feedback, and allocation
-----------------------------------

Acceleration, velocity, and contraction references are integrated directly
in q_x/q_y.  Each is Euclidean-projected onto its configured two-dimensional
L1 ball.  Expansion through G_b^T happens only after these limits, so the
acceleration, velocity, and contraction states retain zero common and
twist-candidate coordinates even after clipping.

Feedback is explicitly two-dimensional:

    f_des = Kp (q_ref - q_actual) + Kd (qdot_ref - qdot_actual).

It does not run four independent tendon PD controllers.  Actual contraction
is neutral_length - measured_length and actual contraction velocity is
-measured_tendon_velocity before applying q = 1/4 G_b s.

The allocator performs the following lexicographic problem, with T=0.01 N:

    level 1: min ||G_b t - f_des||^2, subject to 0 <= t_i <= T;
    level 2: among all level-1 minimizers, min ||t - t_bias||^2.

The feasible bending-effort set is exactly |f_x|+|f_y| <= 2T.  Level 1 is
therefore the Euclidean projection of f_des onto that diamond.  For a fixed
active set at level 2, fixed variables are removed and free variables solve
A_F t_F = r.  Production computes the orthogonal projection of the bias onto
this affine set using an explicit SVD pseudoinverse; its null-space
displacement is zero.  It enumerates all 3^4 lower/free/upper active sets and
selects the global minimum bias distance.  This is not an arbitrary
numpy.linalg.lstsq representative.

There is no checker/twist-candidate optimization level.  The strictly convex
level-2 objective has a unique tension result, so a later checker objective
would either be redundant or violate lexicographic priority.  Common and
checker efforts are diagnostics only.

Preload and common terms
------------------------

Gate C2-C2 v1 sets t_bias and fixed preload to four exact zeros.  The
fixed-root closed loop does not require a fixed preload.  The allocator may
produce a positive mean tension to realize signed bending with nonnegative
tendons; this is reported as dynamic_common_offset_n and is not called
preload.  physical_common_effort_n is the response to an actual four-equal
tension command.  These three terms remain distinct.

Calibration Gate
----------------

For the supplied rounded 0.002 N tail-contraction matrix, the Hadamard modal
vectors diagonalize the symmetric matrix.  Its singular values are

    [148.999, 148.999, 0.0262, 0.0002] um,

so the rounded decimal matrix has algebraic rank 4 and full-matrix condition
number approximately 7.45e5.  The ratios are sigma_2/sigma_1=1 and
sigma_3/sigma_2=1.76e-4.  This algebraic rank must not be confused with
effective physical rank: the two tiny directions are dominated by chord
nonlinearity/measurement scale and have no independently resolved common or
axial-rotation response.  A direct 4x4 inverse would amplify those rejected
directions and has neither a sound numerical nor physical interpretation.

The 2400/4800 Hz, repeated, 0.002/0.006/0.010 N probes found sigma_1 and
sigma_2 approximately 0.0745 m/N, sigma_2/sigma_1 approximately 1, stable
retained-subspace principal angles no greater than 2.11e-8 rad, and frequency
uncertainty norm 1.49e-6 m/N.  The small third chord singular value scales
linearly with probe tension after division by the tension, identifying a
quadratic bending-shortening chord rather than an independent linear mode.
Four-equal physical common excitation produced zero response in this plant.

Checker probes use [T,0,0,T] and [0,T,T,0], each with actual common offset
T/2.  Half their response difference removes common effort.  No tendon, tip,
or axial-rotation response was resolved.  This coordinate remains named
twist-candidate; it is not claimed to be physical twist without tip/joint
axial rotation evidence.

The Gate must stop rather than freeze a global matrix if future probes show a
changed effective rank, a material sigma_3/sigma_2 ratio, inconsistent +/-
axis signs, non-determinism, or retained-subspace movement beyond the bound
derived from measurement uncertainty and the sigma_2/sigma_3 gap.

Fault and disabled semantics
----------------------------

The compatible controller starts and resets disabled.  A disabled control
cycle writes four exact zero tensions and does not advance the reference.
After explicit enable, zero acceleration retains the reset/hold reference
semantics; with the v1 zero bias it does not add fixed preload.

An allocator or internal compatibility numerical failure writes four exact
zeros, records the exception reason and control tick, and latches the fault.
Later cycles remain at zero and do not automatically recover.  reset() or
clear_fault() is required explicitly.  Invalid caller values remain ordinary
ValueError programming errors and do not silently become plant faults.

Data-driven acceptance
----------------------

Allocator tests cover feasible/infeasible random efforts, diamond edges and
vertices, degenerate/multiple-solution cases, several biases, all manifest
permutations, an independent closed-form pair oracle, and a dense grid.  The
production package has no SciPy dependency.

With Kp=400 N/m, Kd=0.05 N*s/m, 0.04 m/s^2 accelerate/decelerate pulses and a
100 um modal reference, fixed-root +/-X and +/-Y runs at 2400 and 4800 Hz
settled to approximately 88.31 um in the measured tail.  Peak commanded
tension was 3.03 mN, no allocator saturation/fault, warning, or contact was
observed, cross-axis response was below 1e-12 m, and the maximum cross-rate
transient q difference was 0.101 um.  These values are regression contracts
for this validity envelope, not a claim of zero steady-state error.


Gate C2 final: calibrated static feedforward and free-UAV validation
====================================================================

Final controller preset
-----------------------

``scaled_stablesoft_bending_controller_config()`` and
``make_scaled_stablesoft_bending_controller(tendon_names)`` freeze the final
configuration.  The tendon names must come from the runtime-resolved manifest
bindings; numeric tendon or actuator IDs are not configuration inputs.

The final parameters are:

    control frequency                 240 Hz
    valid MuJoCo simulation rates     2400 and 4800 Hz
    acceleration L1 envelope          0.04 m/s^2
    modal velocity L1 envelope        0.002 m/s
    modal contraction L1 envelope     0.000300 m
    calibrated actual-q L1 envelope   0.000400 m
    Kp                                300 N/m
    Kd                                0.02 N*s/m
    K_static                          diag(52.58, 52.58) N/m
    Ki                                not present
    allocator tension bounds          0 <= t_i <= 0.010 N
    allocator bias/fixed preload      [0, 0, 0, 0] N

The static term is

    f_static = K_static q_reference.

It is a calibrated equilibrium effort in the two retained tendon bending
modes.  It is not acceleration inverse dynamics, does not use tendon mass,
and is not a 4x4 tendon inverse.  Modal PD and static effort are summed before
the unchanged lexicographic bounded allocator.  Setting
``static_feedforward=None`` explicitly restores the prior PD-only computation
path; regression tests compare that path exactly.

Feedforward calibration and choice
----------------------------------

The original 100 um PD-only profile reaches the reference exactly but settles
near 88.307 um: its approximately 11.693 um error is the equilibrium effort
needed to balance joint elasticity/gravity at finite Kp.  The allocator is
unsaturated with zero primary residual, cross-axis motion is negligible, and
the reference/common/checker diagnostics are exact, so reference integration,
allocation, coupling, and saturation are not the source of that offset.

A new 3 s quasi-static matrix used 2, 5, and 10 mN commands, both signs,
X/Y axes and diagonals, both simulation rates, and repeated runs.  The
training mean modal stiffness was 52.5771 N/m.  All measured training and
holdout values were 52.5205--52.6159 N/m; the 2400/4800 mean difference was
3.97e-5 N/m, cross-axis response was zero to numerical scale, and repeats
were bitwise identical.  This supports the rounded linear diagonal value
52.58 N/m.  The measured variation is too small to justify a piecewise or
higher-order model, and no integral state is needed.

The final feedback gains were selected jointly with the free-UAV Gate.  The
old 400 N/m, 0.05 N*s/m pair remains the frozen C2-C2 PD-only regression but
is too close to the free-base discrete stability boundary.  The final
300 N/m, 0.02 N*s/m pair retains fixed-root accuracy while avoiding saturation
in the validated free-UAV window.

Fixed-root validated workspace
------------------------------

The final preset was tested at 75, 136, 200, and 250 um reference magnitudes
over signed X/Y axes and all represented diagonal signs.  Profiles include
accelerate--decelerate--hold, zero-acceleration hold, direction reversal,
projection/rejection of incompatible four-tendon inputs, sustained allocator
saturation and release, reset, disable/re-enable, injected numerical failure,
explicit clear, and manifest permutation.

Across the formal fixed-root holdouts:

    maximum absolute tail error        0.0159 um
    maximum hold RMS error             1.812 um
    maximum overshoot                  7.90 percent
    maximum 2-percent settling time    0.375 s
    maximum commanded tension          7.784 mN
    saturation fraction                0
    maximum allocator residual         numerical zero
    maximum cross-axis q               below 1e-12 m
    maximum 2400/4800 q difference     0.0332 um
    maximum 2400/4800 tip difference   0.835 um

Power is sampled from synchronized diagnostic copies so the live MuJoCo call
sequence remains identical to the C2-C2 regression.  Generalized, actuator,
tendon-coordinate, and command power agree to machine precision.  The tested
work range was approximately 0.20--1.86 uJ and the maximum fixed-root energy
ledger residual was 3.2 nJ.

Ideal-tension comparison
------------------------

The 0.002, 0.005, and 0.010 N ideal-tension baselines remain unchanged and
continue to record tendon state, tip/joint motion, actuator/generalized force,
power, position/kinetic/total energy, warnings, contacts, and range margins.

For matched final modal contractions at 0.002 and 0.005 N, the acceleration
controller differs from the ideal-tension baseline by at most 0.0092 um in q
and 0.426 um at the tip.  Its peak tensions are approximately 2.585 and
5.850 mN.  The profiles have different power/work because their command
histories differ; this comparison demonstrates similar tendon-modal and tip
motion effects, not physical equivalence of acceleration and tension inputs.

The 0.010 N ideal baselines reach approximately 381 um L1 modal contraction
for both axis and diagonal patterns.  That is outside the controller's frozen
300 um reference envelope.  The controller does not enlarge max_tension or
its reference range to reproduce this boundary case.

Free-UAV active coupling
------------------------

The unchanged C1-B3 gravity/open-loop-hover plant was driven by the external
controller at 240 Hz.  Formal runs cover +/-X, +/-Y, a diagonal, 2400/4800 Hz,
disabled compatibility, enabled hold, explicit disable, fault injection and
clear.  A separate public-API smoke test calls ``env.step(rotor_rpm)`` with a
four-vector while the controller writes a separate four-tension vector.

The validated active free-UAV reference is 5 um with a 0.75 s active window.
Its tail response is approximately 5.0377 um, peak tension is at most
0.220 mN, and there is no saturation, fault, out-of-envelope diagnostic,
warning, contact, or range violation.  The controller acceleration sequences
are exactly equal across rates; maximum q difference is 0.0213 um and maximum
tension difference is 0.471 uN.

UAV reaction is measurable and directionally symmetric.  Positive q_x
produces positive pitch and subsequent +X motion under the tilted equal-RPM
rotor thrust; positive q_y produces negative roll and subsequent +Y motion.
At 0.75 s, relative hover position and attitude errors are approximately
2.378 mm and 5.165 mrad.  Controller tension changes with the measured free
plant tendon state, while UAV pose changes in response to tendon force and
moment, demonstrating two-way rather than scripted one-way coupling.

Equal open-loop hover RPM is not an attitude controller.  After explicit
tension disable, acquired lateral velocity and attitude persist: the 3 s
relative drift is approximately 0.44 m and 0.05 rad.  This is recorded plant
response and must not be described as stable long-duration hover.  No rotor
controller was redesigned to hide it.

External composition and lifecycle
----------------------------------

The controller is owned outside ``BaseAviary``; no environment API or RPM
action was changed.  A typical headless loop is:

    bindings = resolve_ideal_tendon_actuator_bindings(
        env.model, env.SCALED_STABLESOFT_ARM_MANIFEST
    )
    tendon_ids = np.asarray([item.tendon_id for item in bindings])
    controller = make_scaled_stablesoft_bending_controller(
        [item.tendon_name for item in bindings]
    )
    controller.reset(
        env.data.ten_length[tendon_ids],
        env.data.ten_velocity[tendon_ids],
    )
    controller.enable()

    tension = controller.update_bending_acceleration(
        bending_acceleration_cmd_m_s2,
        env.data.ten_length[tendon_ids],
        env.data.ten_velocity[tendon_ids],
    )
    state = controller.state
    env.set_scaled_stablesoft_tension_command(tension)
    observation, reward, terminated, truncated, info = env.step(rotor_rpm)

``rotor_rpm`` and ``tension`` are separate four-vectors.  The update returns
the tension tuple for backward compatibility; complete diagnostics are read
from ``controller.state``.

Lifecycle meanings are deliberately distinct:

* disabled: writes four exact zeros and does not advance the reference;
* enabled after reset plus zero acceleration: holds the reset reference and
  produces zero tension with zero preload;
* enabled after a nonzero reference plus zero acceleration: continues the
  compatible modal hold, including calibrated feedforward;
* reset: replaces neutral lengths/reference state, clears a fault, and leaves
  the controller disabled;
* clear_fault: clears only the latch and preserves the current reference;
* fault-latched: writes four exact zeros until reset or explicit clear.

Scope and exclusions
--------------------

The fixed-root guarantee is vertical, gravity-on, collision-disabled,
no-contact, and limited to the stated small-deformation envelopes.  The free
UAV guarantee is the smaller active window above plus bounded post-release
safety, not closed-loop hover.  A short public-step small-attitude smoke test
is finite and contact-free, but contact tracking performance is not designed
or claimed.  Hardware motors, spools, FOC/current loops, tendon mass,
curvature/tip inverse kinematics, force/impedance contact control, trajectory
generation, and a UAV attitude controller remain separate future stages.
